# Playbook: fix-bug

修一個回報的缺陷：先重現、找根因、修、補回歸測試。

這是範例 playbook，示範格式。步驟用中性語言指名 skill，不綁單一工具的指令語法
（不要寫 `/diagnose` 這種 Cursor slash command）。實際的 skill 名換成你引入或自寫的。

## 何時用

有一個可重現的缺陷要修，不是加新功能、不是重構。

## 步驟

1. 重現缺陷。寫一個會失敗的測試或一段能穩定觸發的步驟，證明缺陷存在。沒重現就不往下。
2. 用 diagnose skill 找根因。追到系統第一個出錯的地方，不是症狀出現的地方。
3. 在根因處修。改動越小越好，只碰與這個缺陷直接相關的程式。
4. 用第 1 步的測試驗證修好了。回歸測試留下來，讓同一缺陷再犯時會被擋。
5. 用 pr skill 開 PR。內文寫清楚：缺陷是什麼、根因在哪、怎麼修、怎麼驗證的。

## 完成條件

- 第 1 步的紅燈變綠燈。
- 回歸測試已加入並通過。
- 沒有順手改動與缺陷無關的程式。
