# rules/

Rule sources, one `<name>.md` per rule. `scripts/install-rule.sh` converts each
into the target tool's own rule format at install time (not a symlink, because
Kiro steering and Antigravity rules use different frontmatter).

Empty by default: this kit ships the tooling, not the rules. Add rule files when
you decide which ones to carry.

Two ways to add a rule file:
- Write your own `.md` directly in this format.
- Import one from an upstream repo with `scripts/import-rule.sh <source> <file_path> <local_name> [kit_load]`
  (sources are in `upstream/rule-sources.tsv`). Imported rules get a `kit_source`
  frontmatter line and are tracked for upstream changes by `check-updates.sh` and
  `diff-upstream.sh --rule <local_name>`.

## Source file format

A plain Markdown body with a kit frontmatter block. Example:

```markdown
---
kit_load: always          # always | glob | manual | model
kit_targets: all          # all | kiro | antigravity  (comma-separated)
title: Reply writing style
description: How to write replies and reports.
globs: "*.md"             # only for kit_load: glob
---

# Reply writing style

...rule body...
```

- `kit_load` — when the rule activates. `model` has no Kiro equivalent; on Kiro
  it installs as `manual` and `install-rule.sh` prints a warning.
- `kit_targets` — which tools get this rule. Use to keep machine-specific rules
  (e.g. a shared-server rule) off the home machine.
- `description` — required for `model`, recommended otherwise.
- `title` — used for Kiro's `title:`. Defaults to the file name.

## How each tool receives the rule

| kit_load | Kiro `inclusion` | Antigravity `trigger` |
|----------|------------------|------------------------|
| always   | always           | always_on              |
| glob     | fileMatch (*)    | glob                   |
| manual   | manual           | manual                 |
| model    | manual (warned)  | model_decision         |

## Install targets

| tool | global | workspace |
|------|--------|-----------|
| Kiro | `~/.kiro/steering/<name>.md` | `<ws>/.kiro/steering/<name>.md` |
| Antigravity | `~/.gemini/config/rules/<name>.md` | `<ws>/.agents/rules/<name>.md` |

```bash
scripts/install-rule.sh kiro
scripts/install-rule.sh antigravity
scripts/install-rule.sh all --workspace ~/proj
```

Installed rule files carry a `# generated by agent_skill_kit` marker on line 1.
Re-running overwrites only files that carry that marker; a hand-written rule of
the same name is left untouched and reported.

(*) Kiro's exact `fileMatchPattern` syntax for multiple patterns is not yet
confirmed. `install-rules.sh` writes the raw `globs` value through. Verify a
`glob` rule loads correctly the first time you install one on Kiro.
